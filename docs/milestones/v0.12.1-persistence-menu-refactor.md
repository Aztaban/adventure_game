# v0.12.1 Task List — Persistence/Menu Refactor and Hardening

Status: planned after v0.12 acceptance
Goal: audit and harden the implemented one-slot persistence and menu flow without changing player behavior or save compatibility.

## Working rule

Do not assume every task requires source changes. Complete the audit first, classify later tasks as required/reduced/skipped, and preserve the v0.12 save format and player flow.

## R121-01 — Audit the completed v0.12 implementation

No v0.12.1 source changes should be made during this task.

- [ ] Trace Save Game from pause result through confirmation, snapshot creation, envelope creation, path resolution, temporary write, and atomic replacement.
- [ ] Trace Continue/Load from save-status detection through envelope/snapshot validation, session restoration, transient-state reset, and final application mode.
- [ ] Trace Escape, Back, Confirm, F11, Controls return, pause, and confirmation modal priority.
- [ ] Count duplicated save parsing/status checks, error translation, path construction, confirmation state, and event/update/draw branches.
- [ ] Confirm filesystem code does not leak into `GameState`, interaction services, or concrete screen objects.
- [ ] Confirm the v0.12 save-format contract and full automated baseline before changes.
- [ ] Record real-Pygame/manual findings, including menu readability and modal behavior.
- [ ] Mark R121-02 through R121-05 as required, reduced, or skipped with evidence.

Exit condition:

```txt
The v0.12.1 scope is evidence-based and smaller than the v0.12 feature implementation.
```

## R121-02 — Clarify persistence ownership

Classification: decision-gated by R121-01.

When duplication or coupling is demonstrated:

- [ ] Keep snapshot creation/restoration independent from JSON and filesystem concerns.
- [ ] Keep path resolution authoritative and injectable for tests.
- [ ] Consolidate envelope validation, atomic write, and read/error translation only where responsibility is duplicated.
- [ ] Keep one manual-slot API small; do not introduce a repository pattern without multiple storage implementations or slots.
- [ ] Preserve atomic replacement and previous-save protection.
- [ ] Preserve the v0.12 file format and error behavior.

Skip condition:

```txt
Skip source extraction when the implemented path/envelope/I/O functions already have clear ownership and tests.
```

## R121-03 — Review menu and navigation ownership

Classification: decision-gated by R121-01.

- [ ] Review `GameApp` branches for title, Controls, gameplay, pause, ending, and confirmation behavior.
- [ ] Review whether concrete menu/screen objects own only layout, local selection, drawing, and semantic results.
- [ ] Keep `AppMode` and explicit navigation when they remain understandable.
- [ ] Introduce the smallest screen contract or stack only if duplicated event/update/draw/navigation logic is concrete and substantial.
- [ ] Do not add settings, extra slots, autosave, or unrelated screens during this refactor.
- [ ] Preserve all menu labels, confirmation rules, and modal priority.

Skip condition:

```txt
Skip a screen abstraction when current branching is clearer than the abstraction that would replace it.
```

## R121-04 — Consolidate save status and error presentation

Classification: decision-gated by R121-01.

- [ ] Confirm title Continue and pause Load use one definition of valid/missing/invalid/unsupported/unreadable status.
- [ ] Consolidate repeated status parsing or exception-to-message mapping when found.
- [ ] Keep technical diagnostics available without exposing raw exceptions as player copy.
- [ ] Avoid long-lived save-status caching unless measured filesystem access or stale UI behavior proves it necessary.
- [ ] Do not add migrations while only save-file version 1 is supported.
- [ ] Add focused tests for any consolidated status/error boundary.

Skip condition:

```txt
Skip changes when save status already has one source of truth and player messages do not duplicate technical mapping.
```

## R121-05 — Regression hardening

Classification: required after any accepted refactor; otherwise reduced to audit-gap tests.

- [ ] Protect fresh, mid-quest, selected-item, changed-scene, and completed save compatibility.
- [ ] Protect missing, invalid JSON, invalid envelope, unsupported version, invalid snapshot, unreadable, and write-failure behavior.
- [ ] Protect last-valid-save survival after failed replacement.
- [ ] Protect failed-load preservation of the current session and mode.
- [ ] Protect transient-state clearing and completed-save ending restoration.
- [ ] Protect Escape/modal priority, removed `N`, and global `F11` behavior.
- [ ] Protect title Continue validity and pause Load availability.
- [ ] Run formatting, lint, focused tests, full suite, and the complete demo-flow integration test.
- [ ] Complete real-Pygame pause/save/load/confirmation checks.

Milestone acceptance:

```txt
- Save format and player behavior remain compatible with v0.12.
- Persistence, snapshot, menu, and application responsibilities are clear.
- Error/status behavior has one source of truth where duplication existed.
- GameApp remains understandable or has only the smallest evidence-based navigation boundary.
- No repository, migration system, autosave, settings system, or general UI framework was added without evidence.
```

## Boundary with the new movement plan

This audit remains behavior/save-compatible with accepted v0.12. Do not introduce
player coordinates, navigation, animations, or legacy movement-save upgrades here.
Those belong to v0.13-v0.15; the known snapshot-v1 fallback is implemented in v0.14.
If the audit reveals no source refactor, close it with evidence and only the necessary
regression/documentation changes. A separate .1 release is not mandatory.

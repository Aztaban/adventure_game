# v0.11 Task List — Display and Controls Foundation

Status: planned  
Goal: support fullscreen and approved window sizes while keeping the existing `1280 x 720` logical game and reliable mouse interaction.

## Working rule

Complete one task at a time. After each task:

```txt
1. run focused tests
2. run make check
3. perform the listed manual check
4. record changed files and intentional behavior
5. commit the task before starting the next one
```

Do not start v0.11.1 cleanup until every accepted v0.11 behavior works.

## D110-01 — Confirm display behavior

Decision checkpoint before code changes:

- [ ] Confirm `1280 x 720` as the logical render resolution.
- [ ] Choose the initial windowed presets. Recommended starting set: `1280 x 720`, `1600 x 900`, and `1920 x 1080`.
- [ ] Choose the startup mode: windowed or fullscreen desktop.
- [ ] Decide whether arbitrary drag-resizing is deferred. Recommended: defer it and use approved presets first.
- [ ] Confirm fullscreen toggle input. Recommended: `F11`.
- [ ] Decide whether display mode persists now or waits for v0.19 settings persistence. Recommended: wait.
- [ ] Record the decisions in this file before implementation.

Exit condition:

```txt
The accepted physical display behaviors are explicit and do not require scene-coordinate changes.
```

## D110-02 — Protect the current fixed-resolution behavior

- [ ] Add or update tests that state the logical resolution contract.
- [ ] Protect title, gameplay, and ending drawing at `1280 x 720`.
- [ ] Protect existing menu mouse hit testing before coordinate conversion is introduced.
- [ ] Run the complete existing suite.

Manual check:

- [ ] Run the current game at `1280 x 720` and capture any existing alignment issues before changing display code.

Exit condition:

```txt
The pre-v0.11 presentation behavior is protected by tests.
```

## D110-03 — Introduce semantic input actions

- [ ] Define the actions needed by the current game and v0.11 menus.
- [ ] Include at minimum: primary action, cancel, dialogue advance, menu up, menu down, menu confirm, new game, and fullscreen toggle.
- [ ] Keep actual Pygame keys/buttons in one binding catalog.
- [ ] Keep player-facing labels in or derivable from the same catalog.
- [ ] Update title/ending menu handling to use semantic actions instead of local raw-key checks.
- [ ] Preserve existing controls unless an approved v0.11 decision changes them.
- [ ] Add focused input-binding tests.

Manual check:

- [ ] Start, navigate, confirm, cancel, advance dialogue, and start a new game using every documented input.

Exit condition:

```txt
Menus and gameplay translate events through one consistent action vocabulary.
```

## D110-04 — Add logical rendering and output scaling

- [ ] Create one `1280 x 720` logical drawing surface.
- [ ] Draw title, gameplay, ending, and debug presentation to the logical surface.
- [ ] Calculate one aspect-preserving destination rectangle for the physical window.
- [ ] Clear unused physical-window space for letterboxing/pillarboxing.
- [ ] Scale and present the logical surface into the destination rectangle.
- [ ] Keep scene and UI drawing coordinates unchanged.
- [ ] Add focused tests for scale and offset calculations where they can remain Pygame-light.

Manual checks:

- [ ] Verify title, Village Square, Forest Path, Ancient Tower, dialogue, prompts, and inventory at each approved size.
- [ ] Verify circles/rectangles and text are not stretched independently in X/Y.

Exit condition:

```txt
Every screen renders through the same logical surface and aspect-preserving presentation path.
```

## D110-05 — Convert pointer coordinates

- [ ] Convert physical mouse positions into logical coordinates before menu or scene hit testing.
- [ ] Use one authoritative conversion for mouse motion and mouse button events.
- [ ] Treat pointer positions outside the presented logical rectangle as non-interactive.
- [ ] Preserve inventory-before-world target priority.
- [ ] Add tests for center, scaled edges, offsets, and letterbox rejection.

Manual checks:

- [ ] Click every menu action and representative world/inventory targets at every approved size.
- [ ] Confirm letterbox areas do not highlight or activate targets.

Exit condition:

```txt
Drawing and hit testing agree at all supported physical resolutions.
```

## D110-06 — Add windowed/fullscreen switching

- [ ] Add the approved windowed modes.
- [ ] Add fullscreen desktop mode.
- [ ] Implement the approved fullscreen toggle action.
- [ ] Preserve the current `GameSession`, scene, dialogue, inventory selection, and menu mode while switching.
- [ ] Recalculate viewport geometry after every display-mode change.
- [ ] Handle display recreation errors clearly without corrupting gameplay state.
- [ ] Add application-level tests for mode changes where practical.

Manual checks:

- [ ] Toggle from title, gameplay, dialogue, and ending.
- [ ] Confirm repeated switching does not move scene targets or reset progress.

Exit condition:

```txt
Display mode changes are presentation-only and do not restart or mutate the game session.
```

## Explicit non-goals

- editable key bindings
- arbitrary UI reflow
- camera/world coordinates
- save/load menus
- persistent settings
- general screen or widget framework
- asset cache redesign

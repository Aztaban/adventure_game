# v0.11 Task List — Display and Controls Foundation

Status: planned  
Goal: support fullscreen and approved window sizes while keeping the existing `1280 x 720` logical game and reliable mouse interaction.

## Working rule

Complete one task at a time. After each task:

```txt
1. run focused tests
2. run make check
3. perform the listed manual check
4. record changed files and intentional behavior
5. commit the task before starting the next one
```

Do not start v0.11.1 cleanup until every accepted v0.11 behavior works.

## D110-01 — Confirm display behavior

Decision checkpoint completed before code changes:

- [x] Use `1280 x 720` as the logical render resolution.
- [x] Support the initial windowed presets `1280 x 720`, `1600 x 900`, and `1920 x 1080`.
- [x] Start the game in fullscreen desktop mode.
- [x] Defer arbitrary drag-resizing and use only fullscreen desktop plus the approved 16:9 presets during v0.11.
- [x] Use `F11` as the fullscreen toggle input.
- [x] Do not persist display settings during v0.11; every new launch starts in fullscreen desktop mode.
- [x] Return from fullscreen to the last windowed preset used during the current session.
- [x] Use `1280 x 720` as the windowed fallback when no windowed preset has yet been used during the current session.
- [x] Preserve the 16:9 aspect ratio and use letterboxing or pillarboxing instead of stretching.
- [x] Defer persistent display settings and possible arbitrary drag-resizing to the v0.19 settings and packaging milestone.

Accepted behavior:

```txt
Logical render resolution: 1280 x 720
Startup mode:             fullscreen desktop
Windowed presets:         1280 x 720, 1600 x 900, 1920 x 1080
Fullscreen toggle:        F11
Windowed return target:   last preset used during this session
Initial return fallback:  1280 x 720
Aspect ratio:              preserve 16:9 with letterboxing/pillarboxing
Drag resizing:             deferred to v0.19 for a new decision
Settings persistence:      deferred to v0.19
```

Exit condition:

```txt
The accepted physical display behaviors are explicit and do not require scene-coordinate changes.
```

## D110-03 — Introduce semantic input actions

- [x] Define the actions needed by the current game and v0.11 menus.
- [x] Include at minimum: primary action, cancel, dialogue advance, menu up, menu down, menu confirm, new game, and fullscreen toggle.
- [x] Keep actual Pygame keys/buttons in one binding catalog.
- [x] Keep player-facing labels in or derivable from the same catalog.
- [x] Update title/ending menu handling to use semantic actions instead of local raw-key checks.
- [x] Preserve existing controls unless an approved v0.11 decision changes them.
- [x] Add focused input-binding tests.

Implemented action vocabulary:

```txt
PRIMARY            Left Click
CANCEL             Esc
DIALOGUE_ADVANCE   Space / Enter / Numpad Enter
MENU_UP            Up Arrow / W
MENU_DOWN          Down Arrow / S
MENU_CONFIRM       Enter / Numpad Enter / Space
NEW_GAME           N
FULLSCREEN_TOGGLE  F11
```

Notes:

- One physical event may produce more than one semantic action when context decides the meaning. For example, `Space` and `Enter` produce both dialogue-advance and menu-confirm actions.
- Mouse motion remains pointer-position state rather than a command action.
- `F11` is present in the catalog now; display switching is implemented in D110-06.

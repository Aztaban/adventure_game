## D120-04 — Define the save-file envelope and status model

- [x] Define save-file format version 1 separately from the existing snapshot version.
- [x] Wrap the snapshot in a plain JSON-compatible envelope containing at minimum the file version, UTC save timestamp, and snapshot payload.
- [x] Validate envelope shape and types before calling snapshot restoration.
- [x] Distinguish missing, valid, invalid JSON, invalid envelope, unsupported file version, invalid snapshot, and unreadable-file outcomes.
- [x] Keep raw filesystem/JSON exceptions from leaking into player-facing menu code.
- [x] Do not implement migrations; unsupported versions fail safely and clearly.
- [x] Add focused envelope, timestamp, status, and unsupported-version tests.

Implemented facts:

- `game/save_file.py` owns save-file format version `1`, separately from snapshot version `1` in `game/state_snapshot.py`.
- `create_save_file_envelope()` produces only plain JSON-compatible values and normalizes aware timestamps to ISO-8601 UTC with a `Z` suffix.
- `validate_save_file_data()` requires exactly `save_format_version`, `saved_at_utc`, and `snapshot`, validates the UTC timestamp, and validates the snapshot before any session restoration.
- `SaveFileStatus` distinguishes missing, valid, invalid JSON, invalid envelope, unsupported file version, invalid snapshot, and unreadable-file outcomes.
- `inspect_save_file()` and `inspect_save_file_text()` convert filesystem, Unicode, JSON, envelope, and snapshot failures into the status model without returning raw exceptions.
- Unsupported save-file versions return `UNSUPPORTED_FILE_VERSION`; no migration or fallback path exists.
- `validate_state_snapshot()` is now the public non-mutating snapshot-validation boundary. Pygame-bound imports remain deferred until actual session restoration.

## D120-05 — Implement atomic manual-save I/O

- [x] Serialize the envelope as UTF-8 JSON.
- [x] Create the user-data directory only when a write requires it.
- [x] Write a temporary file in the same directory as the final save.
- [x] Flush the completed temporary file and sync it where supported.
- [x] Replace the final save with `os.replace()` only after the temporary write succeeds.
- [x] Clean up temporary files after handled failures where practical.
- [x] Preserve the previous valid manual save when writing, flushing, syncing, or replacing fails.
- [x] Return typed/domain-level failure information suitable for UI messages.
- [x] Add tests for successful writes, replacement, malformed reads, permission/I/O failures, and previous-save preservation.

Implemented facts:

- `write_save_file()` serializes the complete envelope in memory as indented UTF-8 JSON before creating directories or temporary files.
- The destination directory is created with `parents=True` and `exist_ok=True` only after serialization succeeds and a write is requested.
- The writer uses a uniquely named temporary file in the final save directory, writes a trailing newline, flushes it, and calls `os.fsync()` when available.
- The temporary file is closed before `os.replace()` atomically replaces the manual-save path.
- `SaveWriteStatus` and `SaveWriteResult` distinguish success, invalid data, directory creation, temporary-file creation, write, flush, sync, and replacement failures without exposing raw exceptions.
- Any previous manual save remains byte-for-byte unchanged unless `os.replace()` succeeds. Handled failures attempt to close and remove the abandoned temporary file.
- Save writing remains independent from `GameState`, gameplay services, screen objects, and running-session replacement.

## D120-06 — Restore sessions and clear transient presentation state

- [x] Load and validate the save envelope before replacing the active session.
- [x] Restore through the existing `restore_session_from_snapshot()` boundary.
- [x] Replace `GameApp.session` only after the complete load and restoration succeeds.
- [x] Preserve current scene, inventory order, selected item, flags, pickups, completed interactions, and ending state.
- [x] Ensure fresh scene construction clears dialogue, transient messages, hover state, and other scene presentation state.
- [x] Reset title, pause, Controls, ending, and confirmation local selection/state after successful load.
- [x] Enter `PLAYING` for normal saves and `ENDING` immediately for completed saves.
- [x] Keep the previous session and mode unchanged after any failed load.
- [x] Add fresh, mid-quest, selected-item, changed-scene, and completed-save application-level tests.

Implemented facts:

- `GameApp.load_session_from_save()` first calls `inspect_save_file()` and returns its domain status without touching the running session when the save is not valid.
- A valid envelope is restored through `restore_session_from_snapshot()` into a fresh candidate `GameSession`; `GameApp.session` and `AppMode` are assigned only after that complete restoration returns successfully.
- Normal saves enter `PLAYING`; snapshots with `ending_reached` enter `ENDING` immediately over the restored final scene.
- Snapshot restoration remains the single owner of persistent state reconstruction, including scene ID, inventory order and selection, flags, collected pickups, completed interactions, and ending state.
- Fresh scene construction prevents source or previous-session dialogue, interaction/speaker messages, and pointer hover state from leaking into the restored session.
- Successful session replacement resets the existing title, Controls, and ending local selection state plus the Controls return mode. Pause and confirmation objects do not exist until D120-07/D120-08, so they cannot retain stale local state during D120-06; those tasks should extend the same reset point when the objects are introduced.
- Every non-valid `SaveFileStatus` leaves the previous session and mode unchanged. Restoration failures also cannot partially replace them because assignment occurs after restoration.
